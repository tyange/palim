# 자유 배치 캔버스 — 격자 모드 3세대

격자 모드는 더 이상 "행·열에 자소 하나씩"이 아니다. **연속 좌표에 독립된 텍스트
조각(fragment)을 놓고, 조각끼리 겹칠 수 있다.** 시인이 "도화지에 점을 찍듯이" 쓸
수 있어야 한다는 요구에서 나왔다 — 이산 격자(칸 하나 = 자소 하나)로는 겹침을
원천적으로 표현할 수 없어서 모델 자체를 바꿨다. 이전 두 세대(SVG 격자, CM6 + 좌표
맵)는 `archive/discrete-grid-editor/`에 있다.

## 왜 이렇게 짓는가

핵심 질문: "IME·캐럿·undo는 브라우저한테 맡기고, 나머지는 우리가 원하는 대로"가
가능한가?

- **틀린 답(1세대의 실패)**: 캔버스 전체를 커스텀 렌더링하고 **가상 캐럿 하나**로
  전체를 흉내낸다. 캐럿·IME 조합·선택을 전부 손으로 재구현해야 하고, 정확히 이
  지점에서 실패했다(`archive/svg-grid-editor/korean-ime-bug.md`).
- **맞는 답(지금)**: 화면엔 정적 텍스트 조각들만 떠 있고, **지금 편집 중인 조각
  하나에만** 진짜 `contenteditable`을 그 좌표에 얹는다. 그 하나는 브라우저 네이티브
  IME·캐럿·클립보드를 그대로 받고, 나머지는 그냥 화면에 박힌 `<div>`다. 파워포인트·
  피그마·FigJam의 텍스트박스가 쓰는 것과 같은 패턴이다.

시안: `design-system/mockups/palim/freeform-canvas-directions.html`.

## 데이터 모델 (`stores/manuscript.ts`)

```ts
interface Fragment { id: string; x: number; y: number; text: string }
fragments: Fragment[]  // 배열 순서 = 쌓임 순서(나중 = 위)
```

- **좌표는 연속값**(px), 격자에 스냅 안 됨. `text`엔 여러 줄(`\n`)이 들어갈 수 있다.
- **기본 예시**(`defaultFragments`)는 배시은 '현재형 일기'(시집 <소공포>) 발췌를
  원본 지면 배치 그대로 옮긴 것이다. 줄마다 **왼쪽 구절은 x=40에 붙이고 오른쪽
  구절은 공통 오른쪽 끝(481px)에 맞춘** 양끝 배치이고 행 간격은 38px(2em)이다.
  출처 두 줄도 둘째 줄 오른쪽 끝을 481에 맞추고, 원문의 앞 공백(10칸/11칸)은
  그대로 둬 한 칸 들여쓰기 차이를 살렸다. 한때 구절 10개를 흩뿌린 겹침 데모였는데,
  시 전체가 안 보여 "예시가 잘렸다"로 읽혀서 바꿨다.
- 오른쪽 구절의 x는 **Noto Serif KR 19px로 실측한 폭을 481에서 뺀 값을 하드코딩**
  한 것이다. 한글 advance가 글자마다 달라(가 18.35px, 갛 16.43px) 글자 수로 계산할
  수 없다. 폰트나 `CANVAS.fontSize`를 바꾸면 다시 재야 한다. 처음엔 가장 빡빡한
  줄의 사이 간격이 16px인 379로 잡았는데, 좌우 구절이 붙어 보여 블록 폭을
  441px로 넓혔다.
- 블록 폭 441px에 좌우 여백 16px씩이면 473px이 필요하다. 폭 390px 폰에서는
  오른쪽 구절이 화면 밖으로 나간다.
- 위 좌표는 블록 안의 상대 배치다. **처음 로드할 때 블록 전체를 뷰포트 가운데로
  옮긴다**(`window.innerWidth/innerHeight` 기준, 블록 왼쪽·위가 16px 밑으로는 안
  내려가게 클램프). 왼쪽 위에 붙여 두면 넓은 화면에서 한쪽으로 쏠려 보여서다.
  로드 후 창 크기를 바꿔도 다시 옮기지 않는다. 조각 좌표는 문서 내용이라 화면에
  따라 바뀌면 안 되기 때문이다.
- 흐름 모드의 `DEAFAULT_VALUE`와는 따로 관리한다. e2e는 조각 개수(29)만 이 배치에
  기대고, 좌표는 첫 조각 위치를 읽어 상대적으로 쓴다(뷰포트마다 절대 좌표가 달라서).
- 진실원천이 `text`(문자열) 하나였던 이전 모델과 달리, **여기서는 `fragments`가
  독립된 진실원천**이다. 흐름 모드의 `text`와 서로 변환하지 않는다 — 겹친 두 조각을
  한 줄 평문으로 표현할 방법이 없어서 애초에 변환이 정의 안 됨(아래 "잃은 것" 참고).
  모드 토글은 그냥 두 개의 서로 다른 문서를 오갈 뿐이다.
- `core/fragments.ts` — DOM·Vue 모르는 순수 함수: `bringToFront`(배열 맨 뒤로 = 위로
  쌓기), `removeById`. 테스트(`fragments.test.ts`)는 여기 있다.

## 편집 (`components/CanvasEditor.vue`)

- **빈 곳 클릭** → 그 좌표에 빈 조각 생성 + 즉시 편집 모드.
- **기존 조각 클릭**(드래그 아님) → 편집 모드 재진입.
- **드래그** → `f.x`/`f.y` 직접 갱신. Vue가 `:key="f.id"`로 그 DOM 노드를 재사용하니
  드래그 중 `setPointerCapture`가 안 끊긴다(진짜 캔버스라면 흔한 "매 프레임 전체
  다시 그리다 캡처가 끊기는" 함정을 `v-for` diffing이 공짜로 피해준다).
- **편집 모드**: `contenteditable` 하나를 그 좌표에 올린다. `FlowEditor.vue`의
  uncontrolled textarea와 같은 이유로 **텍스트를 반응형으로 바인딩하지 않는다** —
  타이핑 중에 Vue가 다시 렌더하면 커서가 튄다. `nextTick`에서 `textContent`를 한 번만
  명령형으로 심고, `blur`/`Esc`에서만 값을 읽어 커밋한다.
- **Esc 또는 바깥 클릭**으로 커밋. 빈 텍스트로 커밋하면 조각이 삭제된다(별도 삭제
  UI 없음).
- **Esc는 `e.isComposing`일 때 가로채지 않는다**(`onEditorKeydown`). 2벌식 조합
  중에도 Esc를 그냥 blur로 처리하면, "IME 자체의 조합 취소"보다 우리 쪽이 먼저
  편집을 끝내버려 조합 중이던 글자가 어중간하게 잘리거나 편집기가 강제로 닫힌다
  — 실제로 e2e 도입 중 CDP로 재현해 발견한 버그(`e2e/ime.spec.ts`). "IME는
  브라우저에 맡긴다"는 이 컴포넌트의 핵심 전제를 지키려면 조합 중 키 이벤트는
  우리가 아예 관여하지 않아야 한다.
- **드래그 시 텍스트 선택 함정**: `pointerdown`에 `preventDefault()`가 없으면
  브라우저 기본 드래그-선택이 같이 시작되고, 특히 Safari에서 두드러진다. `.frag`에
  `user-select: none`(`-webkit-` 접두사 포함)도 같이 건다.
- **좁은 화면에서 조각이 한 글자씩 세로로 깨지는 함정**: `.frag`/`.frag-editor`엔
  반드시 `width: max-content`가 있어야 한다. `position: absolute` + `left`만 있고
  (`right` 없이) `width`가 `auto`인 요소의 shrink-to-fit 폭은 "그 `left` 지점부터
  containing block(`.canvas`) 오른쪽 끝까지 남은 공간" 기준으로 계산된다 — 뷰포트가
  좁아 조각의 `x`가 이미 `.canvas` 폭을 넘으면 그 남은 공간이 음수가 되고, 브라우저는
  폭을 거의 한두 글자 수준으로 잘라버린다. `white-space: pre-wrap`이 그 좁은 폭에서
  매 글자마다 줄바꿈해 세로쓰기처럼 보인다 — 실제로 모바일 뷰포트 프로덕션에서
  겪은 회귀(`e2e/canvas-editor.spec.ts`의 "좁은 뷰포트..." 테스트가 지킨다). CM6
  시절 `.cm-content`에도 같은 이유로 `width: max-content`를 썼던 전례가 있다
  (`archive/discrete-grid-editor/grid-editor.md`).

## 렌더 (`stores/manuscript.ts`의 `CANVAS` 상수)

`CANVAS.fontSize`/`lineHeight`/`fontFamily`를 편집(`CanvasEditor`)과 미리보기
(`CanvasPreview`)가 공유해 화면이 어긋나지 않는다. `fontFamily`는 흐름 모드와 같은
`--font-manuscript`(Noto Serif KR) — 더는 고정폭이 필요 없다(겹침·자유 배치엔
고정폭이 의미가 없다).

## 미리보기·내보내기 (`components/CanvasPreview.vue`)

`GridPreview.vue`와 같은 패턴(흑백 고정색 SVG + `useExport`의 SVG/PNG 저장)이지만,
칸 중앙이 아니라 **조각의 (x,y)에 그 줄들을 그대로** 찍는다. 여러 줄 조각은 줄마다
`CANVAS.lineHeight`만큼 내려가며 별도 `<text>`로. 캔버스 자체 스크롤 영역이 아니라
전체 조각의 바운딩 박스를 재서 SVG `viewBox`로 쓴다.

## 다중 선택 (`CanvasEditor.vue`)

- **선택은 빈 곳 드래그(marquee)로만** — Shift/Cmd+클릭으로 하나씩 추가하는 방식은
  넣지 않았다. 배경 클릭이 곧 "새 조각 생성"인 이 캔버스에서 클릭 계열 입력을 이미
  많이 쓰고 있어, 별도 조작(드래그)으로 완전히 분리하는 쪽이 덜 헷갈린다.
- **빈 곳 드래그 vs 클릭 구분**은 조각 드래그와 같은 3px 임계값 패턴
  (`onCanvasPointerDown`) — 안 움직이면 기존대로 조각 생성, 움직이면 마키 사각형을
  그리며 겹치는 조각을 실시간으로 선택 집합에 넣는다.
- **히트테스트**: 조각의 `x`/`y`(캔버스 로컬 좌표, 이미 `left`/`top` 스타일과 동일)에
  DOM 실측 `offsetWidth`/`offsetHeight`를 합쳐 AABB 겹침 판정. 폭·높이는
  `contenteditable` 자동 크기라 미리 계산할 수 없어 매번 실측한다.
- **선택 후 상호작용**: 선택된 조각을 드래그하면 전체가 상대 오프셋을 유지하며 같이
  움직인다(release 시 그룹 전체를 순서대로 `bringToFront`). 선택된 조각을 **드래그 없이
  클릭**하면 그 조각 하나만 편집 모드로 들어가고 나머지 선택은 풀린다 — "클릭=단일
  대상 작업, 드래그=그룹 이동"으로 일관되게 나눴다. 배경을 클릭(드래그 아님)하면
  선택을 비우고 새 조각을 만든다(기존 동작과 동일).
- **삭제**: 선택이 있고 편집 중이 아닐 때 Delete/Backspace로 전체 삭제. **Escape**는
  선택만 비운다(편집 중 Escape는 기존대로 커밋). 두 키 모두 팔레트/미리보기 오버레이가
  열려 있으면 무시(`useEditorUiStore`의 `paletteOpen`/`previewOpen` 확인) — 다른 입력에
  끼어들지 않게.
- **정렬/배치**(`SelectionToolbar.vue`, `core/align.ts`): 2개 이상 선택 시 상단에 뜨는
  플로팅 툴바. 좌/가로중앙/우, 상/세로중앙/하 정렬과(2개 이상) 가로/세로 균등 배치
  (3개 이상, 첫/끝 고정하고 간격만 맞춤 — 아이콘·동작 모두 Figma 관례를 따름)를
  제공한다. `core/align.ts`(`alignEdge`/`distribute`)는 좌표만 다루는 순수 함수라
  DOM 실측값(폭·높이)은 호출부(`CanvasEditor.vue`)가 그때그때 넘겨준다 — 폭이 고정이
  아니라서 결과를 캐시하거나 store에 미리 넣어둘 수 없다.

## undo/redo (`core/history.ts`, `stores/manuscript.ts`)

- **커맨드 패턴이 아니라 전체 스냅샷 패턴**을 택했다. 조각 개수가 시 한 편 기준
  많아야 수십 개라 배열 전체를 복사해도 비용이 무시할 만하고, "생성·삭제·이동·정렬"
  전부를 한 종류의 되돌리기로 통일할 수 있어 구현·검증이 훨씬 단순하다.
  `core/history.ts`의 `History<T>`는 `past`/`future` 두 스택만 다루는 완전히
  범용·순수 클래스 — 값이 뭔지, 어떻게 복제하는지 전혀 모른다.
- **복제는 호출부(store) 책임**: `structuredClone(fragments.value)`를 썼다가
  `DataCloneError`로 즉시 실패했다 — `fragments.value`는 Vue 반응형 Proxy라 구조적
  복제 알고리즘이 이해할 수 없는 내부 트랩을 가진다. `core/fragments.ts`의
  `cloneFragments`(각 원소를 얕은 스프레드로 복사)가 항상 안전하다 — `Fragment`가
  중첩 없는 평면 객체라 얕은 복사로 충분하다.
- **스냅샷 시점 = "커밋 직전"**, 매 픽셀/매 타이핑이 아니다: 드래그는 3px 임계값을
  넘어 `moved`가 처음 `true`가 되는 그 순간(아직 위치를 바꾸기 전 상태) 한 번,
  텍스트 편집은 `commitEdit`에서 실제로 값이 달라졌을 때만, 정렬/균등 배치는
  계산된 결과가 비어 있지 않을 때만. 그래서 "그냥 클릭만 하고 취소" 같은 무변화
  액션은 undo 스택에 안 쌓인다.
- **새 조각 생성 vs 기존 조각 재편집**: 새 조각은 커밋(비어있지 않은 텍스트로
  blur)되기 **전까지 `fragments` 배열에 아예 안 들어간다**(`isNewFragment` 플래그로
  구분). 그래서 생성을 undo하면 빈 텍스트 유령 조각이 남는 게 아니라 조각 자체가
  깨끗이 사라진다.
- **⌘Z/⌘⇧Z는 편집 중이 아닐 때만** 가로챈다(`editingId === null` 가드) — 조각
  텍스트를 타이핑하는 도중의 ⌘Z는 그 `contenteditable`의 **브라우저 네이티브
  undo**(글자 단위)로 그대로 흘려보낸다. 구조적 undo(생성·삭제·이동·정렬)와 텍스트
  키스트로크 undo는 서로 다른 히스토리라 섞지 않는다.
- undo/redo 후에는 **선택을 항상 비운다** — 되돌리기로 존재가 사라지거나 좌표가
  바뀐 조각을 계속 선택된 것처럼 보여주면 `SelectionToolbar`의 개수·정렬 기준이
  실제 화면과 어긋난다.
- **흐름 모드는 손 안 댐**: `<textarea>` 자체가 브라우저 네이티브 undo/redo를
  공짜로 갖고 있어 별도 구현이 필요 없다. `stores/manuscript.ts`의 `fragmentsHistory`
  는 `fragments`(격자 모드)만 추적한다.
- 스택 크기는 `History`의 `limit`(기본 50)으로 제한 — 무한정 쌓이지 않게.
- `CommandBar.vue`에 격자 모드에서만 보이는 실행취소/다시실행 아이콘(`canUndo`/
  `canRedo`로 비활성화 상태 표시) — 단축키를 모르는 사용자를 위한 발견 경로.

## 방향키 넛지 (`core/fragments.ts`의 `nudge`)

- 선택된 조각(들)을 방향키로 1px, Shift+방향키로 10px씩 옮긴다. 마우스 드래그보다
  미세 조정이 훨씬 정확해서 — 다중 선택·정렬 다음의 자연스러운 다음 단계였다.
  마키로 선택한 조각이 하나뿐이어도 그대로 동작한다(정렬처럼 2개 이상을 요구하지
  않음).
- `nudge(fragments, ids, dx, dy)`는 `bringToFront`/`removeById`와 같은 자리
  (`core/fragments.ts`)에 있는, 배열을 제자리에서 바꾸는 순수 함수. 좌표는 드래그와
  동일하게 0에서 클램프한다(캔버스 밖 음수 좌표 금지라는 기존 불변식 유지).
- **연타/길게 누름을 undo 한 단계로 묶는다**: 매 keydown마다 스냅샷을 찍으면 방향키
  하나 꾹 누르고 있다가 ⌘Z 한 번에 겨우 1px만 되돌아오는 게 된다. 그래서 "이전
  넛지로부터 500ms 안에 또 넛지했나"를 보는 유휴 타이머(`nudging` 플래그 +
  `nudgeIdleTimer`)로 연속 입력을 한 세션으로 묶어 그 세션 시작 시점에만
  `store.snapshot()`을 찍는다 — 정렬/이동/삭제처럼 "커밋 시점에만 스냅샷" 원칙의
  변형이다(위 "undo/redo" 참고).

## 복제 (`core/fragments.ts`의 `duplicateSelected`, ⌘D)

- **클립보드 기반 ⌘C/⌘V가 아니라 ⌘D 하나로 복제**했다 — `navigator.clipboard`는
  비동기·권한 요청이 필요해 동기적인 키보드 흐름과 안 맞고, 이 앱엔 앱 간 붙여넣기
  같은 클립보드 특유의 요구가 없다. Figma/Sketch의 "⌘D = 제자리 복제"가 이 캔버스의
  선택 모델과 그대로 들어맞는다.
- `duplicateSelected(fragments, ids, makeId, dx=16, dy=16)`는 선택된 조각들을
  `(dx, dy)`만큼 밀어 배열 끝에 복제(=맨 위로 쌓임)하고 새 id 목록을 반환하는 순수
  함수. id 생성은 콜백(`makeId`)으로 주입받아 `core/`가 여전히 store를 모른다.
- 복제 직후 **복제본이 선택된다**(원본 선택은 풀림) — 그대로 드래그해서 옮기기
  좋게. 그래서 ⌘D를 연달아 누르면 매번 "방금 만든 복제본"을 또 복제해 대각선
  계단식으로 퍼진다(Figma와 동일한 체감).
- 선택이 없으면 아무 일도 안 함(정렬·삭제·넛지와 같은 전제).

## 스마트 정렬 가이드 — 드래그 중 스냅 (`core/align.ts`의 `computeSnap`)

- 드래그 중인 조각(들)의 좌/가로중앙/우, 상/세로중앙/하 여섯 기준점이 **다른
  조각의 같은 여섯 기준점** 중 하나와 6px 안으로 가까워지면 그 위치로 딱 맞춰
  붙고, 그 기준선을 세로/가로 안내선(accent 1px)으로 보여준다. `alignEdge`가
  쓰는 것과 같은 여섯 기준점 개념이라 "정렬 버튼 없이 드래그만으로도 정렬되는"
  느낌으로 자연스럽게 이어진다.
- **x·y축을 독립적으로 스냅**한다(Figma와 동일) — 가로로만 맞고 세로는 안 맞는
  상황이 흔해서, 축 하나가 어긋났다고 다른 축까지 스냅을 포기하면 안 된다.
- 축마다 **가장 가까운 후보 단 하나만** 선택한다(여러 조각·여러 기준점이 동시에
  임계값 안에 들어와도). 그래야 안내선이 한 축에 여러 개 뜨며 헷갈리는 일이
  없다.
- **다중 선택 드래그도 스냅된다**: 선택된 조각들의 합집합 바운딩 박스를 "움직이는
  사각형"으로 보고 스냅 델타를 계산해 그룹 전체에 동일하게 적용한다 — 그룹을
  하나의 덩어리처럼 다루는 게 직관과 맞는다.
- `computeSnap(rect, others, threshold=6)`은 좌표·크기만 다루는 순수 함수
  (`core/align.ts`, `AlignRect`를 재사용). DOM 실측(폭·높이)은 드래그 로직
  (`CanvasEditor.vue`)이 매 `pointermove`마다 새로 구해 넘긴다 — `alignEdge`/
  `distribute`와 같은 이유(조각 크기가 고정이 아니라 미리 계산해둘 수 없음).
- 스냅은 **드래그의 최종 델타에 얹는 보정**이라 undo와 별도로 취급하지 않는다 —
  드래그 시작 시점(`moved`가 처음 `true`가 되는 순간)에 이미 스냅 이전 원본
  위치로 스냅샷을 찍어뒀으므로, undo 한 번으로 스냅 여부와 무관하게 드래그
  시작 전 상태로 정확히 돌아간다.

## 잃은 것 (알고 가는 트레이드오프)

- **평문(.txt) 내보내기 불가**: 겹친 두 글자를 같은 자리 평문으로 표현할 방법이
  없다. 이 모드의 "진짜" 산출물은 이제 텍스트가 아니라 이미지(SVG/PNG). Palim의
  "공백 하나까지 그대로 전사"라는 원래 전제와는 다른 종류의 작업이 됐다 — 배치형
  시를 "옮겨 적는" 게 아니라 "새로 짓는" 쪽에 더 맞는 모드다.
- **모드 전환 시 내용 보존 안 됨**: `fragments`와 흐름 모드 `text`가 서로 독립이라,
  격자 ↔ 흐름을 오가도 상대 모드의 내용이 바뀌지 않는다(이전엔 같은 텍스트를 두
  모습으로 보여줬지만 이제는 애초에 변환이 안 되는 두 개의 문서다).
